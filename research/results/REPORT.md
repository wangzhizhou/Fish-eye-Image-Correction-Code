# 简明研究结论

详细推导、证据与行号见 [`../REPORT.md`](../REPORT.md)。

## 数学

* **auxFunc(w,φ) = sgn(ψ)·2 sin w · sin(|ψ|/2) / sin(w+|ψ|/2)**，ψ = π/2 − φ。合法域 w ∈ (0, 3π/4)，在 φ 上严格递减，赤道处 C¹ 连续。
* **h(w) = auxFunc(w,0) = 2 sin w/(sin w+cos w) = √2 sin w / sin(3π/4−w)**，与论文 Eq.17 一致。
* **LCCP(ω)** = 北半球从子午圆上的固定点 X=(cos2ω, sin2ω) 向切线中心投影（南半球用镜像点）。ω=π/2 为 Braun 球极柱面投影 2tan(ψ/2)。
* **getPhi(l) = 2 atan(l/(4−l))**；**getPhi1(l,w) = π/2 − sgn(s)·2 atan(|s| sin w/(2 sin w − |s| cos w))**，s = h − l。
* 四种镜头的焦距公式在 FOV=180° 时均正确（f/R = 1/2、2/π、1/√2、1）。
* 验证：SymPy + 50 位 mpmath 33/33 项通过；首次运行的 2 个失败是检查写错，已在报告 §7.6 记录。

## C++ 实测（第二阶段，research/cpp_harness/）

* 原始 `program/`（未修改）用 OpenCV 4.14.0 + clang 21 编译通过，0 个错误。旧 C API 宏由 `highgui_c.h`/`core_c.h`/`imgproc_c.h` 提供，这些头文件在 OpenCV 5 中已删除 ⇒ **4.x 可编译，5.x 不可编译**（BUG-26）。
* **仓库 `resources/corrected0–3.jpg` 被逐字节复现**：圆参数 (946,634,623)、Correction3、JPEG q95。
* **改正第一阶段的错误**：`cv::Point(u,v)`（double 参数）是**截断**，不是四舍五入（C4 采样表 100% 与截断一致，只有 25% 与四舍五入一致）。受影响的结论已改正：仓库输出与 Python 复刻的 MAE 由 2.72 降为 0.80（就是 JPEG 本身的误差）；整数往返偏置由 (−0.93,−1.49) 改为 (−1.44,−2.00) px（C++ 坐标编码图实测为 (−1.61,−2.63) px）。
* getPhi、getPhi1（5 个 w）、static 缓存的结果与 Python 移植**逐位相同**；auxFunc 相差 ≤2.2e-16；cvFastArctan 相差 ≤3.1e-5°。CircleFitByKasa 42 组点中 41 组相同，另 1 组的差别是 1e-12 量级舍入误差在截断时落在整数的不同一侧。
* 原来只有代码审查依据的 6 项缺陷，经 C++ 实测：BUG-12（ASan：main.cpp:53 heap-buffer-overflow）、BUG-15（FOV=0.8π 时正反向相差平均 20 px）、BUG-16（ret.jpg 被写出并覆盖）、BUG-23（拼接失败时退出码为 0）、BUG-26 **全部确认**；BUG-24 的坐标颠倒**确认无影响**，360×180 几何假设仍未验证。
* BUG-06 越界读：按 build.sh 的选项（不定义 NDEBUG）编译时，OpenCV 的 `Mat::at` 断言会触发，进程以未捕获的 cv::Exception 中止；定义 NDEBUG 时为 ASan 可检测到的 heap-buffer-overflow。

两项新的实测结论：
* **镜头模型**：六组图像的旋转自标定一致表明，这台相机的镜头是**等立体角、视场约 183°**（2 px 内一致的匹配 57–83%）。代码和论文假设的等距 180° 只有 1–11%；按等距 180° 校正，最大径向角误差约 3°（≈21 px）。
* **投影选择**：按立体角加权的形状形变，main 使用的 C3（0.405）劣于论文的 C4 ω=π/2（0.185）。C3 在地平线边缘把物体横向拉长 1.84 倍。（更正：论文中"车辆被拉长"的车辆位于赤道以下，那里论文自己的 C4 也会横向拉长，ψ=−45° 时 1.21 倍；原因是 LCCP 本身，增大 ω 可减轻。详见 `../PAPER_REVISION.md` J9。）形状最优为经度线性 + LCCP ω≈1.81（0.088）。第二阶段建议的 ω=3π/8 在这一度量下并不好（0.418），已在 REPORT §14 修正。

## Correction3 / 4 / 5

* main 实际使用 **Correction3**：纬度、经度**都**用 Braun（w=π/2）。论文 Eq.17 要求经度线性，与之一致的是 **Correction4**。默认参数下 C3 与 C4 **不等价**。
* `w_longtitude` 从未参与计算。
* C4 与 C5 在 **EQUIDISTANCE** 下互逆：连续往返误差 6e-12 px；源码数值 ≤0.25 px；整数像素管线（两处都截断，C++ 实测行为）平均 2.69 px，含 (−1.44,−2.00) px 偏置；两处都改为四舍五入后为 1.05 px、无偏置。其他镜头模型下不互逆（18–131 px），因为 C5 写死了等距模型。
* C5 正向映射空洞率：R=623 时 9.2%，R=256 时 36%。

## 主要缺陷（共 26 项：Python 移植上有测试 14 项，C++ 实测 17 项）

1. getPhi 的伪根 + |f| 停止准则 ⇒ 赤道 φ 误差 0.0123 rad，输出中心十字"马赛克"——**在原程序输出 corrected0.jpg 中可见**（C++ 实测，逐字节复现）。
2. func1/getPhi1 的 `static` 缓存 ⇒ 换 w 后纬度错乱（最大 90°）。
3. VALS "距离 < 均值"过滤保留较差的点对；N=3 时干净图像也会失败；对噪声和亮斑极敏感（中心误差 31–140 px）。
4. Kasa 结果截断为 int（最大 1 px 偏置）；main 忽略圆检测失败。
5. FOV<180° 时 C3/C4 有 25–64% 的输出像素采样到鱼眼圆外。
6. C5 越界读、每次调用写 `ret.jpg`、输出尺寸写死 512、main.cpp L52 越界。
